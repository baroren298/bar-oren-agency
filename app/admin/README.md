# `app/admin/`

Placeholder folder for the admin panel UI (Admin Panel Architecture v1.2, Section 2).

**Phase 2 (Auth/Security) added:** `layout.jsx` (root layout — required since this folder sits outside `app/[locale]/`, which is the de-facto root for the public site) and `login/page.jsx` + `login/LoginForm.jsx` + `login/login.module.css` (Owner login form, posts to `app/api/admin/auth/login/route.js`).

**Phase 4 foundation sprint added:** `page.jsx` — a minimal `/admin` dashboard landing page (title, welcome line, one nav link to `/admin/talent`). No new auth code was needed: proxy.js already gates every `/admin/*` path except the allow-listed `/admin/login`, so `/admin` is protected by that existing check. The post-login redirect in `login/LoginForm.jsx` now points to `/admin` instead of `/admin/talent`.

**Phase 4 layout/design-system sprint added:** a reusable admin shell — `AdminShell.jsx` (header + sidebar + content wrapper), `AdminNavLinks.jsx` (client, active-link highlight for the two working routes: Dashboard → `/admin`, Talent → `/admin/talent`), `AdminLogoutButton.jsx` (client, posts to the existing `/api/admin/auth/logout` route), and `admin-shell.module.css` (a small, self-contained token set inspired by — but independent from — `css/styles.css`, so admin styling still can't drift the public site). `page.jsx`, `talent/page.jsx`, and `talent/[id]/page.jsx` now import and render inside `<AdminShell>` instead of each supplying their own `<main style={...}>` wrapper; `/admin/login` is untouched and stays shell-less. No auth, Prisma, or middleware changes — purely presentational.

**Known cleanup needed:** an `app/admin/(dashboard)/` folder exists alongside this README from an abandoned first attempt at this sprint (a Next.js route-group version of the same shell). It duplicates `page.jsx` for `/admin`, `/admin/talent`, and `/admin/talent/[id]` and **must be deleted** before running `next build` — Next.js will fail with a duplicate-route error otherwise. It was left in place because file deletion wasn't available in the session that built this; delete the whole `app/admin/(dashboard)/` directory, nothing else needs to change.

**Phase 2 (Agency Workflow) added:** `my-work/page.jsx` + `my-work/WorkflowItemCard.jsx` + `my-work/my-work.module.css` — the "My Work" dashboard (Drafts / Waiting for Approval / Changes Requested / Approved-Published), reusing `AdminShell`, `PageHeader`, `Card`, `StatusBadge`, and `EmptyState` from `components/admin/**`. Data comes from `lib/admin/mock-workflow.js` (local mock only — no database, no Prisma, no new API route). `AdminNavLinks.jsx` gained a "My Work" link between Dashboard and Talent. No auth, middleware, or public-site changes.

**Admin Hebrew + Friendly Home sprint added:** the admin UI is now Hebrew-first — `app/admin/layout.jsx` already set `lang="he" dir="rtl"`, and this sprint translated the actual on-screen copy (nav, page titles, "My Work" section labels, status/metadata labels, mock item content) to match. All Hebrew strings are centralized in `lib/admin/i18n/he.js` rather than hardcoded per component, so a future `en.js` (plus a small lookup-by-locale helper) could be added later without rewriting every screen — there is deliberately no language switcher yet, per this sprint's scope. `app/admin/page.jsx` (the dashboard) was also reworked into a warmer, work-focused landing: a Hebrew greeting plus a compact summary of "Waiting for Approval" / "Changes Requested" / "Recently Published" counts, read from the same `lib/admin/mock-workflow.js` data `/admin/my-work` uses — no new data source. `admin-shell.module.css`'s sidebar border/margin were switched from physical (`border-right`, asymmetric `margin`) to logical properties (`border-inline-end`, `margin-inline-start`) so the layout doesn't silently assume LTR. No auth, middleware, Prisma, or public-site changes.

**Talent Workspace Foundation sprint** reworked `talent/page.jsx` and `talent/[id]/page.jsx` from a plain read-only table/field-list into the product vision's "talent workspace": the list is now a work queue (`TalentQueueRow.jsx`, built from `Card`/`StatusBadge`) showing each talent's derived workflow status and a one-line summary instead of directory-style columns, and the detail page is now a workspace shell — a header (name, status, last updated) plus five placeholder section tabs (`TalentWorkspaceTabs.jsx`: פרטים / גלריה / רשתות / SEO / היסטוריה), with only פרטים populated (the same read-only published-version fields the old page showed, now Hebrew-labeled) and the other four intentionally empty-state placeholders — no editing, no approve/reject actions, per this sprint's explicit scope. Status derivation lives in the new `lib/admin/talent-workspace.js`, which only reads from the existing, unchanged engine calls (`talentAdapter.listParents`, `versionService.getCurrentPublished`/`listVersionHistory`) — no repository, adapter, engine, or Prisma changes. One real gap, flagged rather than worked around: the list page's existing lightweight query (`talentRepository.listTalents`) only returns `hasPublishedVersion`/`hasPendingChanges` booleans, with no timestamp and no way to tell a DRAFT from a REJECTED version, so the list can only derive 3 of the 4 workflow states (no "changes requested") and "last updated" renders as "—" there; the detail page has richer data already available via `listVersionHistory` and shows the real status (including "changes requested") and a real last-updated date. Closing that list-page gap needs a small, intentionally-deferred repository change (select `updatedAt` and widen the pending-version filter) — see Follow-up recommendations. No auth, middleware, Prisma, or public-site changes.

**Editing Experience Foundation sprint** built the first real editing UI, scoped to exactly the talent workspace's פרטים section (UI only — no save, no API, no database, no approvals). `talent/[id]/page.jsx`'s `DetailsSectionContent` now renders the new `components/admin/ComparisonView.jsx` instead of a flat read-only field list: a "גרסה מפורסמת" (Current Published) block showing the same published-version fields as before, an arrow divider, and a "עדכון מוצע" (Proposed Update) block with real editable inputs (text/textarea/checkbox/comma-list) seeded from the published values. Edits live in local React state only — closing or reloading the page discards them, by design. The component is intentionally entity-agnostic (it takes a generic `{ key, label, value, type }[]` and knows nothing about talent) so the same Current Published / Proposed Update layout can be reused as-is for Gallery, SEO, Social links, Homepage, About, Contact, and Footer in later sprints — only each entity's own `buildXFields()`-style mapping function needs to be written per content type, following the pattern in `talent/[id]/page.jsx`'s `buildDetailsFields()`. The four other workspace tabs (גלריה / רשתות / SEO / היסטוריה) are untouched empty-state placeholders. `talent-detail.module.css` had its now-unused flat field-list styles (`.fieldList`/`.fieldRow`/`.fieldLabel`/`.fieldValue`) removed since `ComparisonView` owns its own styling. No auth, middleware, Prisma, database, or public-site changes.
